# Референсные Мессенджеры и Технологический Стек (`REFERENCE_SYSTEMS_AND_STACK.md`)

Этот документ фиксирует, на какие существующие в мире и в РФ корпоративные мессенджеры мы опираемся как на инженерный бенчмарк, чем наш проект отличается от коробочных решений вроде **ORA / Mattermost / Яндекс.Мессенджер / Signal / Matrix**, и какие именно готовые фреймворки используются на каждом этапе.

---

## 1. На какие мессенджеры мы опираемся (Берем лучшее, отсекаем слабости)

Ни один существующий мессенджер не идеален для задачи **«Удобство Яндекс.Мессенджера + Скорость Discord + Защита уровня Signal/Wire в закрытом или облачном контуре»**. Мы комбинируем 4 проверенных в бою эталона:

| Референс | Что берем у него как эталон | В чем его слабость (которую мы исправляем) |
| :--- | :--- | :--- |
| **1. Wire Enterprise** (Швейцария/ФРГ — госсектор, банки, оборонка) | **Криптографическое ядро.** Именно авторы Wire создали стандарт **IETF RFC 9420 (MLS)** и библиотеку **`openmls`** на Rust. Доказано на практике, что E2EE может работать в корпорациях с SSO и мгновенным увольнением сотрудников. | Тяжеловесный старый серверный стек на Haskell/Scala, сложный в self-hosted развертывании. У нас — легкие статические микросервисы на 100% Rust. |
| **2. Discord** (Мировой эталон HighLoad риалтайма) | **Серверная архитектура на Rust + ScyllaDB.** Discord переписал свои самые нагруженные узлы (в частности сервис `Read States` — миллионы статусов прочтения в секунду, и медиа-шлюзы) на **Rust**, полностью избавившись от фризов сборщика мусора (GC) на миллионах сокетов. | В Discord **нет E2EE для чатов** — сервер читает весь текст в открытом виде. Мы берем их архитектуру доставки, но гоняем по ней зашифрованные конверты. |
| **3. Яндекс.Мессенджер / Compass** (Лидеры B2B UX в РФ) | **Продуктовый UX и облачная синхронизация.** Мгновенный поиск коллег по `@username` и оргструктуре, вход с любого нового ноутбука/телефона с моментальной подгрузкой всей истории чатов, треды, реакции, стабильная работа внутри корпорации на 100k+ человек. | **Нет Zero-Knowledge E2EE.** Шифруется только канал до сервера (TLS), а в базе данных на сервере сообщения доступны администраторам БД / облаку. Мы добавляем **Encrypted Cloud Key Vault**. |
| **4. Коробочные On-Prem решения РФ (ORA, eXpress, Frisbee)** | **Дистрибуция для закрытых контуров РФ/СНГ.** Автономная поставка без внешних облачных зависимостей («без стучалок и Kill Switch»), свой локальный пуш-сервер, работа в закрытом периметре компании. | Защита строится только на уровне периметра («зашифрован виртуальный диск Docker-контейнера»). Если хакер или инсайдер получил root к серверу — вся база читается. У нас даже при полном захвате сервера БД содержит только криптографический мусор. |
| **5. Signal & Matrix (Element)** | От **Signal** — культура аудита памяти и Rust-крейты криптографии. От **Matrix** — концепция зашифрованного облачного бэкапа ключей (Secure Key Backup). | У Signal — «глухая защита» с привязкой к телефону и болью при синхронизации истории. У Matrix — чудовищно медленный JSON-протокол синхронизации графа (Synapse жрет гигабайты RAM). |

## 2. Готовые инструменты и фреймворки нашего стека (0% велосипедов)

### Стек Этапа 1 (`crates/cryptox-proto` + `crates/cryptox-core`)
Проверено через **Context7 MCP**:
1. **`prost` (`v0.13.x`, `/tokio-rs/prost`) + `bytes`:**
   - Официальный стандарт Protocol Buffers в Rust от команды Tokio.
   - Позволяет описывать бинарные структуры через макрос `#[derive(prost::Message)]` даже без внешней зависимости от `protoc`, сжимая пакеты в 3–5 раз эффективнее JSON и сериализуя миллионы сообщений в секунду.
2. **`openmls` (`v0.9.x`, `/openmls/openmls`) + `openmls_rust_crypto` + `openmls_basic_credential`:**
   - Индустриальная реализация протокола **IETF RFC 9420 (MLS)** на Rust для управления `KeyPackage`, деревьями ключей `TreeKEM` и групповыми/личными сессиями.
3. **`chacha20poly1305` & `aes-gcm` (официальная организация `RustCrypto`):**
   - Аудированные реализации 256-битного AEAD-шифрования (`XChaCha20-Poly1305` и `AES-256-GCM`) для шифрования облачного сейфа ключей (`EncryptedVaultBlob`) и конвертов сообщений с проверкой контекста (`AAD`).
4. **`argon2` + `hkdf` + `blake3`:**
   - `argon2` (`Argon2id`) — защита пароля облачного сейфа от перебора на видеокартах.
   - `blake3` и `hkdf` — сверхбыстрая криптографическая деривация сессионных ключей.
5. **`ed25519-dalek` & `x25519-dalek`:**
   - Де-факто стандарт в Rust для цифровых подписей `Ed25519` и обмена ключами Диффи-Хеллмана `X25519`.
6. **`uuid` (с флагом `v7`, `serde`):**
   - Генерация сортируемых по времени идентификаторов по стандарту **IETF RFC 9562 (`UUIDv7`)**.
7. **`zeroize` (с флагом `derive`):**
   - Автоматическое принудительное затирание ключей и паролей в оперативной памяти нулями при удалении объекта.
8. **`proptest` + `criterion`:**
   - `proptest` — генеративный фаззинг (автоматическая проверка тысяч случайных мутаций битов).
   - `criterion` — статистически точный фреймворк нагрузочных микробенчмарков.

### Стек Этапов 2–5 (Микросервисы, Базы данных и Клиент)
1. **`tokio` (`v1.x`)** — главный асинхронный рантайм Rust.
2. **`axum` (`v0.8.x`, `/tokio-rs/axum`) + `tower` + `tower-http`** — веб-фреймворк и бинарный WebSocket-шлюз от команды Tokio.
3. **`tonic` (`v0.14.x`, `/grpc/grpc-rust`)** — высокопроизводительный gRPC-фреймворк для стриминга между микросервисами.
4. **`quinn`** — чистая Rust-реализация протокола **QUIC (RFC 9000)** для мгновенной работы на мобильных сетях без обрывов.
5. **`opaque-ke`** (от Cloudflare / Meta) — реализация стандарта **IETF RFC 9807 (OPAQUE)** для входа без передачи пароля на сервер.
6. **`rusty_paseto`** — криптографические токены **PASETO v4** (безопасная замена JWT).
7. **`sqlx`** — асинхронный драйвер к **PostgreSQL 18** с проверкой SQL-запросов на этапе компиляции.
8. **`async-nats`** — официальный Rust-клиент к брокеру **NATS JetStream** (суб-миллисекундная шина событий для изоляции микросервисов).
9. **`rusqlite` (`bundled-sqlcipher`) + `tantivy`** — зашифрованная локальная БД на клиенте + поисковый движок на Rust (аналог Apache Lucene) для полнотекстового поиска по расшифрованным чатам за `< 5 мс`.
10. **`tauri` (`v2.9.x`, `/tauri-apps/tauri`)** — фреймворк для сборки легкого десктопного и мобильного приложения с бинарным мостом `InvokeBody::Raw` к нашему `cryptox-core`.
