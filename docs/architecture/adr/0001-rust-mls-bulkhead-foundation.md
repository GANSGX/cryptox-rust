# ADR-0001: Выбор 100% Rust, архитектуры Bulkhead и модели Encrypted Cloud Key Vault

- **Дата:** 2026-11-23
- **Статус:** Принято (Accepted)
- **Затрагиваемые модули:** Все крейты `crates/*` и микросервисы `services/*`
- **Связанные стандарты:** IETF RFC 9420, RFC 9750, RFC 9807, RFC 9562, NSA CNSA 2.0, NIST SP 800-207, OWASP ASVS v5.0 L3

## 1. Контекст и проблема
Нам необходим корпоративный мессенджер для компаний масштаба до **100 000+ сотрудников**, который одновременно обеспечивает:
1. Удобную облачную синхронизацию истории чатов между устройствами сотрудника (без риска потери рабочих переписок при смене ноутбука/телефона).
2. Криптографическую защиту уровня Zero-Knowledge (сервер хранит и маршрутизирует только зашифрованные данные).
3. Модульную микросервисную архитектуру, где отказ или перегрузка одного модуля (поиск, логин, статусы) не приводит к остановке доставки сообщений в активных чатах.

## 2. Архитектурное решение
1. **Язык и рантайм:** 100% Rust (`tokio`, `axum 0.8`, `tonic 0.14`, `prost`) для исключения уязвимостей памяти (memory corruption CVE) и пауз сборщика мусора (GC) на 100k+ одновременных соединениях.
2. **Криптографическая модель с облачной синхронизацией (RFC 9750 + Encrypted Key Vault):**
   - Серверная сторона разделена на **Authentication Service** (`auth-vault-svc`, `user-directory-svc`) и слепой **Delivery & Storage Service** (`edge-gateway`, `messaging-svc`).
   - Ключи от диалогов хранятся в облачном зашифрованном контейнере (`EncryptedVaultBlob`), который шифруется и расшифровывается исключительно на клиенте (`crates/cryptox-core`) ключом, выведенным через `Argon2id` + `HKDF-SHA512`/`BLAKE3`.
3. **Изоляция отказов (Bulkhead Pattern):**
   - Проверка сессии на `edge-gateway` выполняется автономно в памяти по публичному ключу `Ed25519` (`PASETO v4`) за микросекунды без сетевых вызовов в `auth-vault-svc`.
   - Критический путь отправки сообщения (`edge-gateway` $\leftrightarrow$ `messaging-svc`) не зависит от `user-directory-svc`, `auth-vault-svc` и `presence-receipts-svc`.

## 3. Критерии приемки
- Полное покрытие каждого модуля `unit`, `proptest`, `chaos` (изоляция отказов) и нагрузочными бенчмарками с фиксацией результатов в `docs/benchmarks/`.
