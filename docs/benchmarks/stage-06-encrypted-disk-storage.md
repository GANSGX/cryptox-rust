## 1. Результаты Криминалистических (Forensics) и Crash-Recovery Тестов

Команда запуска:
```powershell
cargo test --package cryptox-storage
```

| Тестовый сценарий | Что проверялось | Результат |
| :--- | :--- | :--- |
| `test_raw_disk_forensics_zero_plaintext_usernames_or_messages_on_ssd` | Запись сотрудника `@alice_top_secret_president` (`"Alice SuperConfidential CEO"`) и сообщений на диск $\rightarrow$ прямое чтение сырых байтов файла `.redb` с файловой системы (`std::fs::read`). Доказано, что в файле БД на диске **0 вхождений** `@username`, **0 вхождений** `display_name` и **0 вхождений** текста сообщения (благодаря слепому индексу `BLAKE3` и шифрованию записей `AES-256-GCM`). | **PASSED** |
| `test_cold_reboot_persistence_and_48_byte_composite_cursor_pagination` | Запись карточек, сейфов `EncryptedVaultBlob`, водоразделов `read_watermarks` и 15 сообщений на диск $\rightarrow$ **полное уничтожение объекта в RAM (`drop(engine)`)** $\rightarrow$ повторное открытие файла с диска (`Cold Boot`). Проверка:<br>1) Первое чтение идет с L2 диска (`l2_disk_reads = 1`) и прогревает L1 кэш, второе идет из L1 (`l1_cache_hits = 1`);<br>2) Курсорная пагинация по 48-байтному ключу `[TenantId \|\| ChannelId \|\| MessageId]` выдает все 15 сообщений страницами по 6 штук без `OFFSET`;<br>3) Попытка открыть файл БД с неверным ключом KMS/HSM возвращает `Err(StorageError::DiskTamperDetected)`. | **PASSED** |
