# Правило 02: Модульная Микросервисная Архитектура и Изоляция Отказов (Bulkhead)

## 1. Жесткие границы модулей
Каждый сервис в директории `services/` проектируется как изолированный отсек (Bulkhead Pattern):
- **`services/edge-gateway`** — держит клиентские соединения (WebSocket / QUIC), проверяет `PASETO v4` токены локально в памяти (по публичному ключу `Ed25519` без обращения к БД или `auth-vault-svc`).
- **`services/messaging-svc`** — критический контур маршрутизации и хранения зашифрованных конвертов сообщений.
- **`services/auth-vault-svc`** — регистрация/логин (OPAQUE), выдача токенов и хранение зашифрованного облачного сейфа ключей (`Encrypted Key Vault`).
- **`services/user-directory-svc`** — поиск пользователей по `@username`, оргструктура компании и выдача публичных ключей (`KeyPackage`).
- **`services/presence-receipts-svc`** — онлайн-статусы, индикаторы набора текста (`typing`) и батчинг статусов прочтения (`read receipts`).

## 2. Запрет каскадных блокировок на Hot Path
1. При отправке сообщения в существующий чат путь пакета ограничен строго цепочкой:
   `Client -> edge-gateway -> messaging-svc -> NATS JetStream / Storage`.
2. На этом пути **запрещены** синхронные gRPC/HTTP-запросы в `auth-vault-svc`, `user-directory-svc` или `presence-receipts-svc`.
3. Все взаимодействия со сторонними модулями выполняются либо через публикацию асинхронных событий в `NATS JetStream`, либо с жестким `timeout <= 50ms` и паттерном `Circuit Breaker`.

## 3. Стандарты данных и БД для масштаба 100k+ сотрудников
- Все идентификаторы сообщений и сущностей — **`UUIDv7`** (сортируемые по времени 128-битные UUID, **IETF RFC 9562**).
- Пагинация истории сообщений — **строго курсорная** (`WHERE channel_id = $1 AND message_id < $2 ORDER BY message_id DESC LIMIT $3`). Использование `OFFSET` и `SELECT COUNT(*)` на таблицах сообщений **строго запрещено**.
- Каждая таблица и запрос обязаны включать `tenant_id` для изоляции корпоративных клиентов.
