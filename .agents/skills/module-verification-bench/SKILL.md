# Скилл: Верификация и Нагрузочное Тестирование Модуля

После реализации любого модуля в `crates/` или `services/` выполни строго по порядку 5 шагов:

## Шаг 1. Статический анализ и запрет паник
```powershell
cargo clippy --workspace --all-targets -- -D warnings
```
Убедись, что в рабочем коде (`src/`) нет необработанных `.unwrap()` на сетевых/пользовательских данных.

## Шаг 2. Unit & Property-Based Тесты (`proptest`)
Запусти тесты модуля, включая генерацию минимум 1 000 случайных/битых наборов данных:
```powershell
cargo test --workspace
```

## Шаг 3. Интеграционный и Chaos-тест (Bulkhead Isolation)
Для микросервисов из `services/`:
1. Проверь работу сервиса с реальным хранилищем.
2. Запусти тест изоляции отказа: отключи соседний сервис и убедись, что текущий модуль не падает, а отрабатывает по локальному кэшу/токену или возвращает управляемый статус деградации за `< 50 мс`.

## Шаг 4. Нагрузочный прогон (`criterion` / `cryptox-loadgen`)
Запусти бенчмарк модуля и сними метрики:
- **Throughput (RPS / msgs per sec)**
- **Latency (`p50`, `p99`, `p99.9`)**
- **Memory footprint (RAM на 1 соединение / операцию)**

## Шаг 5. Запись отчета
Сохрани результаты прогона и параметры железа в `docs/benchmarks/<module-name>-bench.md`.
