# Чек-лист проверки модуля по международным стандартам

| Категория | Стандарт / Код | Что именно проверяем в коде `cryptox-rust` |
| :--- | :--- | :--- |
| **Протокол E2EE** | **IETF RFC 9420** (MLS Protocol) | Ключи сообщений выводятся через TreeKEM / Ratchet с Forward Secrecy (FS) и Post-Compromise Security (PCS). |
| **Архитектура мессенджера** | **IETF RFC 9750** (MLS Architecture) | Строгое разделение Authentication Service (`auth-vault-svc`) и слепого Delivery Service (`messaging-svc`). |
| **Zero-Knowledge Вход** | **IETF RFC 9807** (OPAQUE aPAKE) | Пароль никогда не покидает клиент; сервер хранит только криптографический конверт OPAQUE и зашифрованный Key Vault. |
| **Прозрачность ключей** | **IETF Key Transparency** (AKD) | Публичные ключи пользователей заверяются в append-only дереве Меркла (защита от подмены ключа взломанным сервером). |
| **Гос / Спецслужбы (Крипто)** | **NSA CNSA 2.0** & **NIST FIPS 203/204** | Готовность к постквантовым гибридным схемам (`X25519MLKEM768`), симметричные ключи 256 бит, `SHA-384/512` / `BLAKE3`. |
| **Аутентификация и KDF** | **NIST SP 800-63B** & **BSI TR-02102** | `Argon2id` (минимум 64 МБ RAM), криптостойкий ГСЧ `OsRng`, короткоживущие токены `PASETO v4`. |
| **Zero Trust Сеть** | **NIST SP 800-207** | Каждый микросервис проверяет подпись токена/запроса, изоляция `tenant_id` на каждом уровне. |
| **Защита приложения** | **OWASP ASVS v5.0 Level 3** & **MASVS** | Затирка ключей в RAM через `zeroize`, отсутствие ключей в `localStorage`, защита локальной БД через `SQLCipher`. |
